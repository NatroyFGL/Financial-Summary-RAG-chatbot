# Financial Document RAG System

**Live demo:** _add your Vercel link here after deploying_

A retrieval-augmented generation (RAG) pipeline that lets you ask natural language questions over a private collection of PDF documents. Built with LangChain, FAISS, OpenAI, Hugging Face and MLflow, with a FastAPI web demo deployed on Vercel.

# Project Structure

papers/ — place your PDF documents here

faiss_index/ — vector store built from papers/ (committed so the web demo can load it; delete it to rebuild after adding PDFs)

rag_pipeline.py — the RAG pipeline: indexing, RAG-Fusion retrieval, semantic routing and the LLM router (shared by the CLI and the web app)

chatbot.py — command-line chatbot that logs every run to MLflow

app.py — FastAPI web app: JSON API + chat page

frontend/index.html — the chat page

.env — your API keys (not committed to git)

# How this repo works

Documents are loaded from the papers/ folder, split into chunks, and embedded into a FAISS vector store.
When you ask a question, the most relevant chunks are retrieved and passed to the LLM, which answers strictly based on the provided context with source citations.

# Pipeline

1) Indexing: PDFs are split into chunks, embedded with text-embedding-3-large and stored in a FAISS index saved to disk.
2) Retrieval (RAG-Fusion): the LLM rewrites the question into 4 search queries; results are merged with Reciprocal Rank Fusion.
3) Semantic routing: the question is embedded and matched to the closest persona: METRICS (exact figures, calculations) or SUMMARY (plain-language overview).
4) LLM router: each route also picks a model:
- Route METRICS: gpt-4o-mini (more reliable with exact figures and citation)
- Route SUMMARY: Qwen/Qwen2.5-7b-Instruct (open source model for narrative answers)

The Hugging Face route falls back to OpenAI automatically if the API is down, rate-limited or no token is set.
5) MLOps: each CLI run logs its config, chosen route, the model that actually answered, latency and the Q&A to MLflow.

# Web demo

The web page shows each answer with clickable page citations and a "How this answer was found" trace:
the generated search queries, the retrieved passages with their fusion scores, the semantic route with
its similarity scores, and which model answered (including when the fallback kicked in).

API:
- POST /api/ask with {"question": "..."} returns the answer plus the trace
- GET /api/health reports whether the server is configured and warms up the pipeline
- Interactive API docs at /api/docs

The public demo is rate-limited per visitor so it can't run up the OpenAI bill.

# Setup

Install dependencies:
pip install -r requirements-dev.txt

(requirements.txt has only what the web app needs, which is what Vercel installs; requirements-dev.txt adds MLflow, PyMuPDF and uvicorn.)

Create a .env file in the project root:
OPENAI_API_KEY=your_key_here
HUGGINGFACEHUB_API_TOKEN=your_hf_token_here  # optional, enables the open-source model route

Add your PDF files into the papers/ folder (then delete faiss_index/ so it is rebuilt).

# Usage

Run the command-line chatbot:
python chatbot.py

You will be prompted to enter a question. The answer will be printed and logged to MLflow.

Run the web app locally:
uvicorn app:app --reload
then open http://127.0.0.1:8000

To view MLflow experiment logs:
mlflow ui --backend-store-uri sqlite:///mlflow.db

# Deploy to Vercel

1) Import this GitHub repo at https://vercel.com/new (Vercel detects FastAPI automatically, no config needed).
2) Add the environment variables OPENAI_API_KEY (required) and HUGGINGFACEHUB_API_TOKEN (optional).
3) Click Deploy. Share the production URL (your-project.vercel.app).

# Notes

The FAISS index is saved locally after the first run so it does not rebuild on every execution. The LLM is constrained to answer only from retrieved document context and will say "I don't know based on the provided documents" if the answer is not found.

LangChain stores the FAISS docstore as a pickle, so it is loaded with allow_dangerous_deserialization=True. That is safe here because the index is generated by this repo; don't load index files from sources you don't trust.
